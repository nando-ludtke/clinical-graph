Strictly Grounded Clinical GraphRAG for Medical Guidelines & Drug Labels

Clinical Graph combines typed dense vector retrieval over guideline prose and tables with a directed clinical knowledge graph so multi-hop therapeutic questions and exact dosing lookups stay verifiably grounded. Every synthesized claim is anchored to verbatim source quotes and inspectable chunk IDs with zero reliance on unverified pretraining memory.

Enable External Web Search?

Web Search queries allowlisted external medical websites (e.g., NIH, NHS, CDC, NICE, WHO, EMA) when local knowledge graph coverage is insufficient. Retrieved passages are screened locally with deterministic pattern checks and wrapped in <source_data> delimiters, but are not scanned by the ML clinical-guard model.

Only enable this if you accept retrieving external web content into the answer synthesis context.

OpenAI Key Modes (for Embeddings, Extraction & Synthesis)

GET /health, GET /v1/documents, and GET /v1/graph run 100% locally with no external API key. For POST /v1/query, POST /v1/query/stream, and document ingestion, two key modes are supported:

  • Server-side env: Set OPENAI_API_KEY in .env (default when no header is sent).
  • Per-request BYOK header: Pass X-OpenAI-API-Key: sk-... on individual requests to override or supply a client key without storing it server-side.
